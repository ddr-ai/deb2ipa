# deb2ipa

An iOS app that takes **any mobile arm64 .deb** - jailbreak-repo apps, GitHub-release debs, or any deb containing an arm64 `.app` bundle - reads its metadata, resolves its dependency tree, and builds an **unsigned .ipa that actually runs** via **GitHub Actions** - for you to sideload on your own iPhone with your preferred tool (AltStore, Sideloadly, or any other).

    +--------+   parse ar +      +----------------+   workflow_dispatch   +------------------+
| deb    |   control.tar   | Classification |  ------------------>  | GitHub Actions   |
| file   | ------------->  | + metadata view |                      | (ubuntu-24.04)  |
+--------+                 +----------------+                      | download deps    |
      ^                                                             | assemble Payload |
      |                                                             | zip unsigned ipa |
   import or URL                                                    +--------+---------+
      |                                                                      |
      |                                                            publish Release
      |                                                                      v
      |                                                            +------------------+
      +----------------------------------------------------------- | download + hand  |
         AltStore / share sheet / your sideloading tool   | off to install   |
                                                                    +------------------+

## What it does

- **Parses every deb** - even debs that cannot be converted get full metadata, dependency tree, and an explanation of why not.
- **Classifies** (content-based, source-agnostic): any deb with an arm64 `.app` bundle is convertible, wherever it came from; tweak-only debs, theme packs and Linux debs are not, and the app tells you exactly why.
- **Resolves dependencies** - the Actions runner fetches Packages indexes from Chariz, Havoc, Procursus, Sileo, BigBoss and any custom repos you add, picks correct versions with real apt version-comparison, and downloads them.
- **Builds unsigned IPAs** - no developer certificate anywhere in the pipeline: pure dpkg-deb extraction plus zip on a Linux runner. AltStore/Sideloadly re-sign at install time; the same artifact works with any sideloading tool you prefer.
- **Self-hosting**: a second workflow builds deb2ipa itself into an unsigned ipa on a macOS runner (tag pushes publish it; app changes run draft smoke builds), so the app is installed exactly like its own output.

## Status

Planning complete - see SKILL.md for the governing build plan and milestone breakdown.

**M1 complete:** the on-device parser package (**DebKit**) is implemented - ar reader, control extraction, DebControl parsing, Depends expressions, and a dpkg-exact Debian version comparator. All unit tests (including real dpkg-deb fixtures for xz/gzip) run green in CI on every push.

**M2 complete:** the classifier reads data.tar, sniffs binaries from their magic numbers (thin arm64 Mach-O, fat Mach-O with an arm64 slice, ELF), finds .app bundles anywhere in the payload, and sorts every deb into five content-based classes - app (convertible when an arm64 executable sits in the bundle), tweak, iOS CLI tools, desktop binaries, or data-only - with a human-readable reason list for every verdict. Tested against 8 real dpkg-deb fixtures in CI.

**M3 complete:** the GitHub API client is in - Keychain-backed PAT storage (protocol-based, with an in-memory store for tests and Linux CI), workflow dispatch with the automatic once-only retry on 404/422 (workflow not synced yet), run polling with 2-30 s exponential backoff and ETag caching (304 responses are rate-limit free), failure-log and release-asset download, and typed, human-readable errors for every failure mode. The workflow input contract with the M4 build (deb_url, package_name, version, bundle_id, display_name, repos, extra_debs) is fixed and tested. 18 tests replay real GitHub API payloads through a scripted transport, and a live test dispatches a real no-op hello workflow whenever a PAT is available (repo secret DEB2IPA_TOKEN or on-device run; see docs/PAT-SETUP.md).

**M4 complete:** the build pipeline is live. `.github/workflows/build-ipa.yml` turns a deb URL into an unsigned `.ipa` on GitHub's ubuntu-24.04 runner: it downloads the root deb, resolves the full dependency closure with the in-repo Python resolver (dpkg-exact version comparison, Provides/alternatives, device-bootstrap virtuals) against Chariz, Procursus and any custom repos you pass, merges every deb's file tree, relocates the surrounding jailbreak bootstrap into the `.app` bundle, generates or validates Info.plist, and packs a Payload-rooted zip that is verified twice before anything is published. The Release carries the `.ipa`, a machine-readable `resolution-report.json` and the full build log - plus an in-workflow asset gate that fails the build if they are missing. Since `GITHUB_TOKEN` cannot start runs but a push can, every change to the pipeline also runs a smoke conversion of NewTerm 3 (a real rootless app; 19 dependencies resolved from Chariz + Procursus, 0 warnings) that publishes only a *draft* release - latest output: a 24 MB `NewTerm.ipa`, all 5021 entries under `Payload/`, arm64 executable and 1111 symlinks intact.

**M5 complete:** the pipeline now proves its own output before publishing. A new launchability checklist dissects every IPA: it parses the arm64 Mach-O headers with a small in-repo reader, walks every `LC_LOAD_DYLIB` of every binary in the bundle and checks it resolves with real dyld semantics (system paths, `@rpath` expansion against the loader's *and* the main executable's run paths, in-bundle staging), verifies the zip structure (single `.app` at the Payload root, Info.plist parses, executable present and arm64, symlink chains intact), and rewrites jailbreak symlink targets into the relocated bootstrap inside the bundle. The results ship as a `launchability-report.json` Release asset and **hard-gate the release**: a failed checklist blocks publishing (the run goes red, the draft stays with full evidence), a passing one publishes. Assembly quality also improved: generated Info.plists derive their identifier from the package name, take the display name from the deb's `Name` field, and raise `MinimumOSVersion` to whatever the executable's `LC_BUILD_VERSION` demands. The whole gate is regression-tested against hand-built Mach-O fixtures - device-absolute dylib paths, dangling symlinks, doubled `.app` bundles and non-Mach-O executables each fail the build; NewTerm 3 passes clean (its `libswift_Concurrency.dylib` resolves `@rpath/libswiftCore.dylib` exactly as it will on-device).

**M6 complete:** the app's UI layer is in - four screens (Import, Builds, Releases, Settings) sharing one environment of observable stores, built so the Linux CI still tests everything: each screen's logic lives in plain Swift files the CI compiles and tests, while the SwiftUI views sit behind `#if canImport(SwiftUI)`. The Import screen parses a local `.deb` instantly for inspection (metadata card, full dependency tree with OR-alternative groups, classification verdict with evidence), and every parser failure is mapped to one of six typed, actionable messages - nothing crashes. Converting stays honest: the GitHub runner needs an http(s) URL to download the deb itself, so the convert button explains itself instead of failing silently. Builds shows the live conversion lifecycle (dispatch, run discovery, polling) and links to the run; Releases lists the workflow's releases with a DRAFT badge and hands the IPA off to your sideload tool - AltStore's one-tap `altstore://install?url=` scheme, the share sheet, or ask-every-time. Settings manages the PAT (stored only in the iOS Keychain, validated against the API on save), the conversion repository and workflow, the apt repos the resolver searches (curated quick-add chips, swipe to remove), and the default handoff. Four new test suites cover the import pipeline's failure map, the display models, the handoff/URL encoding, and the full build-coordinator lifecycle replayed through a scripted transport - all green in CI.

**M7 complete:** the pipeline is hardened and every failure mode is now proven in CI, not just the happy path. A new **convertibility pre-check** runs on the Actions runner right after the deb downloads and *before* any dependency resolution - paste a tweak or theme deb URL straight into the workflow and it fails within seconds with the same explanation the app shows, instead of burning a resolution round-trip. The **large-deb fallback** works end-to-end: debs bigger than a URL-friendly size can be uploaded as a draft release asset, and the pipeline downloads them through a shared fetcher that handles GitHub's signed-redirect auth dance (and falls back to plain curl for public URLs). A new **hardening workflow** runs four end-to-end scenarios on every push: a real app with dependencies through the full green path, a real tweak rejected pre-dispatch, a convertible app with an unsatisfiable dependency (the run goes green only because the failure is the *expected* one - exit 3, a named `UNRESOLVED_DEPENDENCY` machine line, and a report naming the missing package), and a ~60 MB deb round-tripped through the draft-asset path (uploaded, deleted, re-downloaded, converted to a >50 MB IPA, draft cleaned up). The **resolver** is now tested against verbatim stanzas captured from the live Chariz + Procursus indexes (real version strings, Provides pinning, cycle safety) plus an end-to-end fixture repo in real Packages format; the **convertibility check** has 13 cases including both real debs. And a CI gap was found and fixed: the M5 failure-path suite had never actually run in CI - a new `Pipeline scripts (Python)` job now runs all three Python suites on every push alongside the Swift tests. Also caught along the way: the live Chariz index drifted (mobilesubstrate/preferenceloader gone; the NewTerm 3 deb re-uploaded with new dependencies) - the pinned-stanza tests will catch future drift, and the smoke conversion still resolves clean through Procursus plus the firmware virtual.

**M8 complete:** deb2ipa builds *itself*. A new macOS workflow compiles the app with `xcodebuild -destination 'generic/platform=iOS'` and `CODE_SIGNING_ALLOWED=NO` (still certificate-free everywhere), wraps the bare SPM executable into a proper `.app` bundle (complete Info.plist, `MinimumOSVersion 16.0`), packs it into a Payload-rooted unsigned `.ipa`, runs the same M5 launchability checklist against its own output, and attaches the ipa, the report and the build log to a GitHub Release. Pushing a version tag `v*` publishes the public release; pushes that touch the app run a draft *smoke* build instead so the public release list stays clean. The first-ever Darwin compile of the codebase surfaced a handful of platform-specific defects the Linux CI could never see (a removed iOS 26 SDK member, a misspelled argument label the Linux toolchain tolerated, a keyword-colliding enum case, a missing `try` behind a Security guard) - all fixed, and the app's own pipeline is now fully green: the smoke draft carries an 852 KB thin-arm64 `deb2ipa-…-unsigned.ipa` that passes all six launchability checks, ready to sideload with AltStore, Sideloadly, or whatever tool you prefer.
